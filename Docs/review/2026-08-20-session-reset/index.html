2. 완료를 알아내는 신호 4종

PTY는 "명령이 끝났다"를 알려주지 않는다. 에이전트는 셸을 떠나지 않는 장수 프로세스라 프로세스 종료도, 새 프롬프트도 신호가 아니다. 바이트 스트림에 남는 흔적만 쓴다.

#신호어디서 오는가조건지연
1OSC 9 / OSC 777 에이전트가 직접 쏘는 알림 이스케이프. 9;4;(ConEmu 진행률)는 제외 무조건 전달 (작업 중이 아니어도)즉시
2BEL (0x07)claude terminal_bell 채널 작업 중이었을 때만 — 셸 탭완성 실패에도 울림즉시
3진행 표시 소멸 esc to interrupt / esc to cancel / ctrl+c to stop busy 진입 후 2초 침묵 + 총 4초 이상~2초
4출력 정지 에이전트 세션에서 출력이 연달아(≤1.5초 간격) 흐르다 멈춤 세션 확정 + 에코 아님 + 총 8초 이상~2초
세션 확정(agentSeen)은 4번의 안전장치다. 프롬프트나 런처 뒤의 실행 위치에서만 이름을 인정한다 — $ codex, npx @anthropic-ai/claude-code, ❯ codex resume. tokens used, ⏎ send, 진행 힌트도 확정 신호다. 로그 본문에 이름만 스친 INFO starting codex-service는 인정하지 않는다 — 인정하면 그 뒤 모든 로그 스트림이 멈출 때마다 알림이 나간다.

6. 이번에 발견한 문제

보고: "연결이 끊긴 다음 다시 연결해서 진행하면 알림이 정상적으로 안 뜬다."

원인은 하나였다. 감지기는 터미널 인스턴스당 한 번 생성되고, 세션이 바뀌어도 아무 통보를 받지 않았다. 그래서 끊김 경계를 상태가 그대로 넘어갔다.

시간 ─────────────────────────────────────────────────────────────────────────▶ [세션 A] 에이전트 작업 중 ██████████████ busy=true, 2초 타이머 대기 │ 링크 끊김 ───┤ 원격 sshd가 에이전트에 SIGHUP → 작업은 이미 죽었다 │ 그런데 busy 구간과 타이머는 살아 있다 +2초 ─────▶ ① 유령 완료 알림 발화 (죽은 작업에 대한 알림) │ lastDoneAt = now → ② 쿨다운 3초 켜짐 │ 자동 재접속 +3초 ──▶ reconnectPolicy의 첫 간격이 정확히 3초 [세션 B] tmux 재부착, 에이전트 계속 작업 ████ │ 작업 완료 ───▶ ③ 알림이 쿨다운에 먹혀 사라짐 ← "알림이 안 뜬다"

부수 피해

  • 꼬리 오염 — 이전 세션의 tail 80자가 새 세션 첫 청크와 이어져 엉뚱한 마커를 만든다.
  • 하한 오적용 — sawMarker가 남아 다음 완료 판정에 8초가 아니라 4초 하한이 쓰인다.
  • 표시등 잔류 — 세션이 죽었는데 ● 작업 중이 켜진 채로 남는다.

7. 수정

resetForNewSession()을 추가하고 세션 경계 양쪽에서 호출한다.

// TerminalView.tsx — sink 이펙트
agentRef.current?.resetForNewSession();      // ① 새 세션 부착 시

const detach = attachSink(sessionId, (bytes) => { ... });

return () => {
  detach();
  agentRef.current?.resetForNewSession();    // ② 세션이 끊길 때 (대기 타이머 취소)
};
리셋 대상왜
busySince + 타이머죽은 작업에 대한 유령 완료를 막는다 (표시등도 함께 꺼짐)
lastDoneAt쿨다운이 재접속 후 진짜 완료를 삼키지 않게
tail이전 세션 꼬리가 새 세션에서 마커를 완성하지 않게
lastOutputAt, lastUserInputAt옛 타임스탬프로 간격·에코를 오판하지 않게
sawMarker다음 판정에 하한이 잘못 적용되지 않게
agentSeen새 셸이 에이전트 세션이라는 보장이 없다. tmux면 재부착 리드로우가 한 프레임 안에 다시 켠다

검증 — 구현 전 실패를 먼저 확인한 테스트 3개

  • 연결이 끊기면 대기 중이던 완료 판정을 버린다 — 유령 알림 차단
  • 재접속 뒤에도 완료를 정상적으로 잡는다 — 쿨다운 안에서 재접속해도 알림이 나감 (보고된 케이스)
  • 이전 세션의 꼬리가 새 세션 첫 청크와 이어지지 않는다
